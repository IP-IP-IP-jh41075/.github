<h2>「固定」有三种实现方式，含金量不同</h2>
<p>买住宅 IP 时说「固定」，可能指三件事：地址真正长期绑定、长会话内保持不变、或者在一段时间内不主动更换。三种的稳定性差别很大，价格也不同。</p>
<p>搞清这三种，才不会为「固定」两个字多付钱，也不会在重连后突然发现地址变了。</p>

<h2>第一种：真固定绑定</h2>
<p>地址与你的账户长期绑定，无论断线多少次、重启多少次，回来还是这一条。这是最彻底的固定，成本也最高，因为供应商要为你预留资源。</p>
<p>验证方法：主动断开重连三到五次，每次记录地址。全部一致，才算真固定。</p>

<h2>第二种：长会话保持</h2>
<p>只要连接不断，地址就不变；一旦断开重连，可能换一条。这类资源名义上也是静态，实际依赖会话存活。</p>
<p>这种方案日常用起来问题不大，但对账号运营有隐患，因为重连是不可避免的：网络波动、客户端重启、系统更新都会触发。</p>

<h2>第三种：期限内不主动更换</h2>
<p>供应商承诺在某个期限内不主动给你换地址，但上游原因导致的变更不算违约。这是最常见的承诺形式。</p>
<p>这类承诺要看清措辞：是「保证不变」还是「尽力维持」。两者的实际保障差别很大。</p>

<h2>为什么重连测试必须在验收期做</h2>
<p>因为这是唯一能区分三种承诺的办法，而且动作很简单：断开、重连、看地址。整个过程一分钟。</p>
<p>很多人在验收期只做了「能不能用」的测试，没做「重连后还在不在」的测试，结果用到第二周才发现地址会变，这时候已经过了更换窗口。</p>

<h2>购买时要写清的三句话</h2>
<p>第一，这条地址在合同期内是否绑定。第二，重连后是否仍是同一地址。第三，上游原因导致的变更如何处理，是免费替换还是顺延时长。</p>
<p>三句话写进订单备注，比看宣传页有用。愿意写的供应商，通常资源结构也更扎实。</p>

<h2>固定与保活的区别</h2>
<p>固定讲的是「地址不变」，保活讲的是「不被回收」。两者相关但不是一回事：一条地址可能不被回收，但因为上游调整而变更；也可能一直没变，却因为长期无流量被回收。</p>
<p>购买时要分别确认，别把两者混为一谈。</p>

<h2>什么时候不必追求真固定</h2>
<p>短期项目、测试账号、临时任务，这几种场景对固定要求不高，长会话保持就够。为它们买真固定绑定，属于过度付费。</p>
<p>反过来，长期运营的核心账号，真固定带来的稳定性远超差价。</p>

<h2>把「变不变」写进验收单，比写进期望里管用</h2>
<p>验收的时候多加一行：断开重连五次，记录每次的出口地址。五次一致才算通过，有变化就当场提出。这一行只花两分钟，却能避免后面几周反复确认「到底是不是固定的」。</p>
<p>验收单上每多一行可执行的检查，后面就少一次模糊的争论。资源买卖本来信息就不对称，能用动作验证的，尽量别用语言确认。</p>
<h2>常见问题</h2>
<h3>静态住宅 IP 就一定是真固定吗</h3>
<p>不一定。静态更多是一个产品分类，具体是哪种固定要看条款。买之前问清重连后的行为。</p>
<h3>地址变了能要求赔偿吗</h3>
<p>看合同。有变更次数约定的，超了可以谈补偿；没有约定的，通常只能换一条。</p>
<h3>固定地址价格高多少</h3>
<p>通常比长会话类高两三成。具体看地区与数量。</p>
<h3>能不能指定具体某条地址</h3>
<p>部分支持，通常加价。但指定了也不保证永久有效，仍要按合同条款判断。</p>
